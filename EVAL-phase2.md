# Romanian Pro — Phase 2 evaluation (neural next-word model)

Generated by `tools/neural/evaluate_next.py` (dev: λ choice; test: final numbers) and
`tools/neural/report.py`. Raw numbers: `build/neural-eval-dev.json`, `build/neural-eval-test.json`.

## What is compared

| System | What | How it is decoded here |
|---|---|---|
| **(a) Phase 1 `.cngm`** | `Lexicons/ro.cngm` (304,288 pairs), the released Phase 1 next-word model | exactly as in `EVAL.md`: the previous word's first three followers, empty slots filled with the pack's three most frequent words; after 1 letter: followers with that first letter, then the commonest dictionary words with it |
| **(b) neural alone** | the trained official-architecture GRU (PyTorch fp32 weights = `neural/ro.mlpackage` before int8 quantization) | context = the words of the sentence segment before the next word, cleaned by the official `clean_word` (hyphenated words and numbers dropped, as in training), `<bos>` + BPE, last 12 tokens; whole-word decoding by exact best-first search over BPE continuations (see below) |
| **(c) combination** | (a) + (b) | candidates = top-20 `.cngm` followers ∪ the neural model's words ∪ the pack's top unigrams; score = λ·P_cngm(w \| previous word) + (1 − λ)·P_neural(w \| context); λ chosen on dev |

**How Clink combines them is not public.** The engine is closed; the official trainer's comments
say the keyboard "falls back to the bigram" (`.cngm`) when there is no usable neural model, that the
neural model "scores" tokens, and the official README calls it "neural ranking that uses more of the
sentence context". The plausible design is that candidates (dictionary/`.cngm`) are re-ranked with
the neural score; (c) models that as a linear interpolation over the union of both systems'
candidates. (a) and (b) are reported on their own as well.

Whole-word decoding for (b): a word ends with a `</w>` token; `<eos>`, `<unk>`, `<bos>` are never
suggested. The search keeps every partial word whose path probability can still enter the current
top 5 (at most 16 partial words per step, at most 6 tokens per word); identical words reached by
different token paths have their probabilities summed. "After 1 letter": the first token must start
with that letter. Continuation tokens extend the GRU state of the (≤ 12-token) context.
P_neural for (c) is a candidate's canonical BPE path probability (teacher-forced), 0 for words the
neural tokenizer cannot produce (hyphenated forms such as s-a, într-o, which the official cleaner
removes from training and from contexts, as in the official `ro` model whose vocabulary has no `-`).

## Protocol (identical to Phase 1)

Same held-out files (`work/eval/<set>.test.txt`: Tatoeba test, Wikipedia held-out articles,
Wikipedia held-out discussions, Common Voice test), same sampler (2,000 sentences of 2-40 words per
seed; bootstrap resample when the set is smaller), same five seeds, same pair extraction (official
`build-next-word.py` tokeniser; pairs never cross `. ! ? …` or removed markup), same metrics and
intervals (mean ± t(0.975, 4)·sd/√5 over seeds; Δ are paired differences, "(n.s.)" when the interval
includes 0). The (a) numbers reproduce `EVAL.md`'s Romanian Pro column. Neither system has seen any
dev/test sentence: the neural corpus is the Phase 1 training split, from which every near-duplicate of
any dev/test sentence of any source had been removed.

## Summary and ship verdict

- **The neural model alone beats the Phase 1 `.cngm` on every held-out set, beyond noise.**
  Top-3 next word (test): Wikipedia discussions **35.3% vs 26.4%** (+8.9 ± 0.5), Tatoeba
  **31.8% vs 26.2%** (+5.6 ± 0.3), Common Voice **32.8% vs 26.2%** (+6.6 ± 0.2), Wikipedia articles
  **27.0% vs 24.7%** (+2.3 ± 0.2). After the first letter: 59.5 / 60.4 / 60.3 / 49.9% vs
  53.1 / 53.2 / 53.5 / 47.5% (+2.4 to +7.2).
- **The combination is better still, everywhere:** top-3 35.8 / 32.8 / 33.5 / 29.2%
  (+9.5, +6.6, +7.3, +4.5 points over the `.cngm`), after the first letter 60.5 / 62.0 / 61.7 /
  53.2% (+5.7 to +8.8). λ = 0.3 was chosen on dev (best mean top-3 *and* after-1-letter there);
  every λ from 0.1 to 0.6 beats both systems alone on dev.
- **No losses anywhere**: all 16 paired differences are positive with intervals far from 0.
- **int8 weights cost nothing measurable** (dev, simulated exactly as coremltools quantizes:
  neural top-3 changes by ≤ 0.04 points, combination by ≤ 0.15).
- Weak spots of the neural model alone: it can never suggest a hyphenated word (s-a, într-o,
  mi-a …: 1.2-2.4% of the next words here) and it does not see hyphenated words in its context
  (`nu-mi` → the context is empty), exactly like the official `ro` model, whose vocabulary has no
  `-`. The combination recovers those from the `.cngm`.

**Verdict: ship.** The ship gate (beat Phase 1 on top-3 beyond noise on the conversational sets
without big losses elsewhere) is met by the neural model alone (b) and, by a larger margin, by the
combination (c). Conditions before publishing: the macOS compile job must pass its numeric check
(`.github/workflows/compile-neural.yml`), and an on-device check in Clink should confirm that the
pack loads its neural model and that suggestions look like the examples below - these numbers come
from an offline decoder, not from Clink's closed engine.

## The model

| | |
|---|---|
| architecture | official Clink `GRULM` (`vendor/tools/train-neural.py`, unmodified): embedding 128 → 2-layer GRU 256 → projection 128 → tied output, log-softmax; context ≤ 12 BPE tokens |
| parameters | 2,276,612 (official `ro`: 12,050 × 128 embedding, same layers ≈ 2.28M) |
| vocabulary | `neural/ro.bpevocab`, BPE1, 12,036 tokens (32 letters a-z ă â î ș ț ', `</w>`, 12,000 merges, `<unk>` `<bos>` `<eos>`), learned from the training corpus with the official algorithm |
| Core ML | `neural/ro.mlpackage`, 2,377,274 bytes, int8 weights (14 `constexpr_affine_dequantize`), input `tokens` Int32 [1, 1…12], output `logProbs` Float16 [1, 12036] (like the shipped official models); same op graph as the official `ro.mlmodelc` |
| corpus | 2,723,747 sentences / 47.0M words / 64.9M BPE targets from the Phase 1 training split (`source/ro_neural-corpus.json`) |
| training | 80,000 steps × 256 windows ≈ 145.0M targets (1.99 epochs of the mixture: Wikipedia ×0.5, discussions ×3, Tatoeba ×20, Common Voice ×6, other Wikimedia ×3 per epoch), Adam 2e-3 cosine, 5.69 h on 8 vCPUs (4 processes × 2 threads); pilots 0.85 h |
| dev NLL per BPE token | Tatoeba 4.29, Wikipedia 5.38, discussions 4.78, Common Voice 4.30 (best pilot: 5.09 / 6.41 / 5.48 / 5.04) |

## Caveats

- **Offline proxy.** Clink's engine is closed. (b) and (c) are our decoders around the exact network
  that ships; how Clink tokenises the context, decodes words and mixes the neural score with the
  `.cngm` is not public. (a) is the Phase 1 decoder. Differences between systems are what this
  measures; absolute on-device numbers will differ.
- **Evaluated in PyTorch fp32**, the weights that were exported. The shipped model has int8 weights
  (measured: no effect) and computes in fp16 on device (`log(softmax)` in fp16 makes very unlikely
  tokens −inf; the top tokens are unaffected, see the Linux dry run in LOG-phase2.md). The compiled
  model is checked against reference outputs on macOS before installation.
- **Contexts** are the words of the current sentence segment (as in Phase 1's pair extraction),
  cleaned by the official `clean_word`: hyphenated words and tokens with digits are dropped.
- The official `ro` pack's own neural model cannot be run on Linux and is not compared here.
